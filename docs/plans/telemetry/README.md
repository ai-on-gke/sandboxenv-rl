## 3. Starting point and mapping

At `8ff5c3e` (2026-10-21) nothing in sandboxenv-rl was traced or exported as a metric. The Python
client had no telemetry module, `ate-env-api` and `ate-env-guest` served bare `grpc.NewServer()`
instances, `clients/go` had `ClientOptions{Endpoint, GRPCConn}` only, and three benchmark drivers
(the swebench loader, `examples/grpo`, the NeMo Gym rollout benchmark) each wrote their own JSONL
with their own fields and clocks. Upstream, Substrate's `ateapi` already served with
`otelgrpc.NewServerHandler()` and exported `ate_actor_*`, `ate_scheduler_*` and `ate_workerpool_*`
families, so a W3C `traceparent` in gRPC metadata continues a trace into the control plane.

## 4. Design decisions, as settled

1. Propagation carrier: gRPC metadata end to end, as planned. Substrate continues it on its own: the
   atenet router's ingress extracts `traceparent` and resumes the actor under it, `ateapi` stamps
   actor identity on its server span and opens a `step.<name>` span per workflow step, and atelet
   and ateworker follow through otelgrpc and the atelet relay. Every component samples parent-based,
   so a trace the client samples is complete through to the worker once Substrate exports to the
   same backend. No trace-context label on actors is needed (checked against Substrate `28520c0d` on
   2026-10-30).
2. Units and names: seconds everywhere; one histogram bucket set; prefixes `ate_env_client_*`,
   `ate_env_fleet_*`, `ate_env_api_*` and `ate_env_guest_*`. The proposal's `atefleet_*` and
   `atefleet.*` became `ate_env_fleet_*` and `ate_env_fleet.*`.
3. Attribute keys: Substrate's `ate.*` for identities, `ate_env.*` for client-only fields and
   otelgrpc's `rpc.*` for calls, so spans join Substrate's traces and the Go side without a mapping.
   The proposal's `env.*` vocabulary was dropped.
4. Cardinality rule: no environment id, actor id, run id, command line, file path or image tag in a
   metric label or span name; `family` through `repo_family()` with `MAX_FAMILIES`; `atespace` as a
   label on `ate_env_api_create_to_ready_seconds` and `ate_env_api_environments`.
5. Dependencies: extras `tracing` (`opentelemetry-api`, `opentelemetry-sdk`,
   `opentelemetry-exporter-otlp-proto-grpc`, all `>=1.43` with no upper bound; 1.43 is the first
   release whose `opentelemetry-proto` accepts protobuf 7) and `metrics`
   (`prometheus-client>=0.20`). The base install stays `grpcio` and `protobuf`.
6. Config style: frozen dataclasses with the existing unknown-field rejection; `FleetConfig.tracing`
   and `FleetConfig.observability` accept a dataclass or a plain dict; `to_dict()` returns them as
   dicts.
7. Provider ownership: the Python client never replaces an application's `TracerProvider`. With no
   provider and no OTLP endpoint variable, no exporter exists and nothing leaves the process.
8. Python floor 3.10; CI runs 3.12.

## 5. Acceptance, as met

- Base install: `pip install ate-env-client` depends on `grpcio` and `protobuf` only;
  `import ate_env` loads neither OpenTelemetry nor `prometheus_client`
  (`test_registry_import_does_not_load_prometheus`, `test_disabled_tracing_is_a_noop`).
- One trace: `ate_env_fleet.run` to `ate_env_client.*` to `ate-env-api`'s server span to
  `ateapi.Control/*` and the guest, as drawn in [docs/observability.md](../../observability.md).
  #186's end-to-end run on GKE reports 622 spans in 6 traces with 0 orphan roots.
- `/metrics` on the trainer process (`serve_metrics`) and on `ate-env-api` serve the documented
  families; `docs/metrics.md` is generated and CI fails when it is stale.
- `fleet.report.summary()` prints the agent-sandbox-rl table shape
  (`test_report_shape_and_summary_order`).
- The swebench loader's JSONL is unchanged with tracing on or off (`events.golden.txt`), and every
  event has a span.
